# Weather Forecast

Weather Forecast — учебное Android-приложение на русском языке. Оно позволяет найти город через Open-Meteo, сохранить его локально и посмотреть текущую погоду, ближайшие часы, прогноз на 7 дней и весь реально доступный расширенный прогноз.

## Возможности

- **Погодная Главная:** при включённом автоматическом режиме предлагает разрешить приблизительное местоположение, определяет ближайший город системным геокодером и показывает погоду рядом; иначе показывает первый сохранённый город или предлагает выбрать его вручную.
- **Города:** поиск населённых пунктов, карточка текущего местоположения над избранным, отдельное открытие прогноза без сохранения, добавление без дубликатов, текущая температура, погодное состояние, время обновления и отметка устаревшего кэша.
- **Прогноз:** вкладки «Сейчас», «7 дней» и «Месяц», два графика ближайших часов (температура и вероятность осадков), состояния загрузки, обновления поверх кэша, ошибки с повтором и удалённого города.
- **Погодный фон:** состояние считывается именно по цвету без фоновых картинок: ясно — яркий жёлто-золотой, облачно — серый, дождь — глубокий холодный синий, снег — ледяной голубой, гроза — тёмный фиолетовый; светлая/тёмная темы и цвет текста адаптируются отдельно.
- **Настройки:** Цельсий/Фаренгейт, светлая/тёмная тема, переключатель автоматической погоды по местоположению и подтверждаемая очистка всех избранных городов вместе с погодным кэшем.
- **Офлайн:** ранее успешно сохранённая погода читается из Room; смена единиц и темы не требует сети.
- **Фон:** одна уникальная периодическая работа обновляет избранные города примерно раз в 3 часа при наличии подключения.

Геолокация работает только в foreground после объяснения и системного согласия: приложение просит приблизительное местоположение, не хранит координаты и не добавляет найденное место в избранное. Регистрации, фонового отслеживания, push-уведомлений, виджетов, карт, аналитики, рекламы, собственного backend и облачной синхронизации нет.

## Ограничение вкладки «Месяц»

Open-Meteo Forecast API в этом приложении запрашивается с `forecast_days=16`. Поэтому вкладка «Месяц» показывает только реальные дневные записи ответа, максимум 16 дней. Она всегда объясняет ограничение строкой «Доступно до 16 дней» и предупреждает, что точность дальнего прогноза снижается.

Приложение не генерирует, не интерполирует и не экстраполирует искусственный прогноз до 30 дней. Если API вернул меньше записей, отображается только фактически доступное количество.

## Источник данных и API-ключ

Используются публичные HTTPS endpoints:

- Open-Meteo Geocoding API — поиск города;
- Open-Meteo Forecast API — текущая, почасовая и дневная погода.

Для заявленного публичного сценария Open-Meteo API-ключ не нужен. В проекте нет поля, Gradle-секрета или manifest metadata для API key. Перед публичным коммерческим распространением следует отдельно перепроверить актуальные условия использования и требования атрибуции Open-Meteo.

## Технологии

- Kotlin;
- Jetpack Compose и Material 3;
- Navigation Compose;
- Koin, включая ViewModel и `KoinWorkerFactory`;
- Coroutines, Flow и StateFlow;
- Room с migration `1 → 2` и экспортированными схемами;
- SharedPreferences для двух небольших настроек;
- Retrofit + один OkHttpClient;
- WorkManager;
- JUnit, kotlinx-coroutines-test, Robolectric, Compose UI Test и WorkManager Test.

Физическая модульность реализована: `:core:model`, `:core:network`, `:core:database`, `:core:ui`, `:domain`, `:data`, `:worker`, `:feature:home`, `:feature:forecast`, `:feature:settings`. `:app` содержит запуск, навигацию, корневую тему и Koin-сборку модулей. Граф зависимостей описан в [ARCHITECTURE.md](ARCHITECTURE.md).

## Требования для сборки

- Android Studio с поддержкой AGP 9.2.1;
- JDK 17 или новее для Gradle 9.4.1;
- Android SDK Platform 36.1;
- устройство или эмулятор Android API 24+ для ручного запуска.

Локальный путь Android SDK задаётся стандартным `sdk.dir` в некоммитимом `local.properties`. Секреты туда добавлять не требуется.

## Запуск приложения

1. Откройте корень проекта в Android Studio.
2. Дождитесь Gradle Sync.
3. Выберите Android-устройство или эмулятор API 24+.
4. Запустите конфигурацию `app`.

Debug APK можно собрать из корня проекта в PowerShell:

```powershell
.\gradlew.bat assembleDebug
```

Результат создаётся в `app/build/outputs/apk/debug/app-debug.apk`.

Установка APK изменяет состояние устройства, поэтому автоматический рабочий процесс проекта не устанавливает его без отдельного явного разрешения пользователя.

## Проверки

Обязательный локальный набор:

```powershell
.\gradlew.bat testDebugUnitTest
.\gradlew.bat :core:model:test :core:network:test :domain:test :core:database:testDebugUnitTest :core:ui:testDebugUnitTest :data:testDebugUnitTest :worker:testDebugUnitTest :feature:home:testDebugUnitTest :feature:forecast:testDebugUnitTest :feature:settings:testDebugUnitTest
.\gradlew.bat lintDebug
.\gradlew.bat assembleDebug
```

`testDebugUnitTest` проверяет приложение и сквозные Robolectric/Compose integration tests. Тесты моделей, сети, Room, data, Worker и трёх экранов запускаются в принадлежащих им модулях:

- преобразование °C/°F, округление и WMO mapping;
- безопасный JSON/DTO mapping, включая разные длины массивов и отсутствующий weather code;
- Room DAO, транзакционную замену кэша, cascade clear и migration;
- debounce/cancellation поиска и ViewModel state transitions;
- состояния Главной, Прогноза и Настроек через Compose semantics, включая независимые действия «Открыть прогноз»/«Добавить»;
- графики только из реальных почасовых точек, перенос осадков в presentation model, смену °C/°F и доступное текстовое описание;
- сквозной путь «пустая погодная Главная → список и поиск → добавление → Прогноз → Настройки → погодная Главная»;
- временный путь «поиск → открыть прогноз → Back» без записи города в избранное;
- Koin graph и создание Worker через factory;
- unique WorkManager schedule, constraints, backoff и result policy.

Тесты не обращаются к настоящему Open-Meteo: сеть заменяется fixtures/fakes, чтобы результат был детерминированным. Реальный UI и фактическая сеть дополнительно проверяются вручную на подключённом устройстве; без устройства автоматические проверки не считаются доказательством визуального поведения конкретной версии Android.

Если ограниченная среда Windows не разрешает AGP писать в `C:\.android`, можно направить служебный Android home в локальную игнорируемую папку проекта:

```powershell
$env:ANDROID_USER_HOME = (Resolve-Path .\.android-user).Path
.\gradlew.bat -g .gradle-user testDebugUnitTest
```

## Хранение и приватность

- Избранные города и последний успешный прогноз хранятся во внутренней Room-базе приложения.
- Единицы, тема и флаг автоматической погоды по местоположению хранятся во внутренних SharedPreferences.
- Manifest-граф приложения объявляет `INTERNET`, `ACCESS_NETWORK_STATE` и только приблизительное foreground-разрешение `ACCESS_COARSE_LOCATION`; location-разрешение явно указано и в Android-модуле `:data`, которому принадлежит обращение к системному Location API.
- В итоговый merged manifest WorkManager также добавляет служебные `WAKE_LOCK`, `RECEIVE_BOOT_COMPLETED`, `FOREGROUND_SERVICE` и внутреннюю signature-permission для своих компонентов. Они обеспечивают планирование фоновой работы и не дают точный/фоновый доступ к местоположению, контактам, фото или аккаунтам.
- Координаты используются в памяти для HTTPS-запроса прогноза, не сохраняются локально и не выводятся в release-логи. Точный `ACCESS_FINE_LOCATION` и фоновый `ACCESS_BACKGROUND_LOCATION` не объявлены.
- Сеть настроена только на HTTPS; полные ответы API и координаты не выводятся в release-лог.
- Пользователь может согласованно удалить все избранные города и связанный кэш через Настройки.
